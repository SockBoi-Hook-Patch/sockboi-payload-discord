# SockBoi Payload — Northflank Cloud Deployment

คู่มือ Deploy Discord Bot จาก GitHub ด้วย Docker บน Northflank พร้อม Auto Deploy, Persistent Volume, Health Checks และ Graceful Shutdown

> Workload นี้เป็น Discord Gateway worker ที่ต้องเชื่อมต่อค้างไว้ ไม่ใช่ HTTP API
> ใช้ **1 replica เท่านั้น** เพื่อป้องกัน Bot login ซ้ำและ event ทำงานซ้ำ
> Repository: https://github.com/SockBoi-Hook-Patch/sockboi-payload-discord

## สิ่งที่เตรียมไว้
- Python 3.12 + Dockerfile
- FFmpeg และ libopus สำหรับ Voice Greeting / TTS
- non-root user UID/GID 10001
- Persistent JSON state ที่ `DATA_DIR/sockboi_bot_data.json`
- Atomic writes พร้อม flush/fsync/replace
- SIGTERM/SIGINT graceful shutdown
- Health endpoints `/livez` และ `/readyz` บน port 8080
- Discord Gateway reconnect events และ monitoring
- GitHub Actions CI: compile, unit tests, Docker build

## 1. เตรียม Discord Bot
1. ตรวจสอบ Bot Token; หากเคยเปิดเผยให้ Reset ก่อน
2. เปิด **Server Members Intent** และ **Message Content Intent** ใน Developer Portal
3. เชิญ Bot เข้า Server ด้วย permissions ที่จำเป็น
4. วาง role ของ Bot เหนือ Member / Unverified
5. permissions ที่ใช้ขึ้นกับฟีเจอร์ เช่น Manage Roles, Manage Messages, Moderate Members, Kick Members, Manage Channels, View Audit Log และ Connect/Speak สำหรับ Voice

## 2. สร้าง Northflank Deployment Service
1. เข้า https://app.northflank.com/
2. สร้าง Project เช่น `sockboi-payload`
3. เลือก **Add service → Deployment Service**
4. เลือก **Build from a Git repository**
5. เชื่อม GitHub และเลือก `SockBoi-Hook-Patch/sockboi-payload-discord`
6. เลือก branch `main` หลัง Merge Upgrade แล้ว (หรือเลือก feature branch เพื่อทดสอบก่อน)
7. Build Type: **Dockerfile**
8. Dockerfile path `/Dockerfile`; Build context: repository root
9. เปิด **Continuous Deployment / Auto Deploy** สำหรับ branch ที่เลือก

## 3. Environment Variables / Secrets
เพิ่มใน Service → Environment:

| Variable | Required | Value |
|---|---|---|
| `DISCORD_BOT_TOKEN` | Yes | Discord Bot Token (Secret) |
| `GUILD_ID` | Yes | Discord Server ID เป็นตัวเลข |
| `OWN_DOMAINS` | No | โดเมนที่อนุญาต คั่นด้วย comma |
| `WELCOME_VOICE` | No | `1` เปิด Voice, `0` ปิด |
| `PORT` | No | `8080` |
| `DATA_DIR` | No | `/data` |
| `RECONNECT_MONITOR_INTERVAL` | No | `60` วินาที |

เก็บ `DISCORD_BOT_TOKEN` เป็น Secret/Encrypted Variable เท่านั้น ห้ามใส่ใน Git, Dockerfile, README หรือ Build Arguments โปรแกรมจะ fail fast หาก Token ว่าง/เป็น placeholder, GUILD_ID ไม่ใช่เลขบวก หรือ PORT ไม่ถูกต้อง

## 4. Persistent Volume (สำคัญ)
ข้อมูลที่ต้องรักษาข้าม Deploy:
- offense counters สำหรับ spam / nitro
- verification deadlines
- verification alert state
- verification reminder state

ตั้งค่าที่ Service → Volumes:
1. กด **Add volume** และสร้าง Volume ตาม quota ของ Plan
2. เลือก access mode สำหรับ single replica
3. ตั้ง **Container mount path** เป็น `/data`
4. Mount volume root โดยไม่ต้องกำหนด subdirectory
5. บันทึกและรอ Service Redeploy

Image สร้าง user/group UID/GID `10001:10001` เพื่อให้สอดคล้องกับ ownership ของ Northflank Persistent Volume

**ห้าม mount volume ทับ `/app`; mount เฉพาะ `/data` และตั้ง `DATA_DIR=/data`**

## 5. Health Checks
Health server ทำงานภายใน container ที่ port `8080`; ไม่จำเป็นต้องเปิด Public HTTP endpoint

### Liveness Probe (แนะนำ)
| Setting | Value |
|---|---|
| Type | Liveness |
| Protocol | HTTP |
| Port | 8080 |
| Path | `/livez` |
| Initial delay | 60 seconds |
| Interval | 30 seconds |
| Timeout | 5 seconds |
| Failure threshold | 3 |

`/livez` ตรวจว่า process/health server ยังตอบสนอง โดยไม่ผูกกับ Discord Gateway เพื่อป้องกัน restart loop ระหว่าง reconnect ชั่วคราว

### Readiness Probe (ตัวเลือกเสริม)
- Protocol: HTTP; Port: 8080; Path: `/readyz`
- Initial delay 60s; Interval 30s; Timeout 5s; Failure threshold 3

`/readyz` ตอบ 200 เมื่อ Discord client พร้อมและ Gateway connected; ตอบ 503 ระหว่าง reconnect ใช้แสดง readiness เท่านั้น

Northflank health probes เรียก port ภายใน container ได้โดยไม่ต้องสร้าง public port

## 6. Deployment Resources
- Replicas: **1**
- Health check port: 8080 (internal only)
- Persistent volume mount: `/data`
- Stop grace period: อย่างน้อย 30 วินาที หาก UI/Plan มีตัวเลือก
- ห้ามตั้ง replicas มากกว่า 1 สำหรับ Bot instance เดียว

Free Sandbox มี resource limits ตาม Plan ปัจจุบัน ตรวจ Usage/Billing ก่อน Deploy และไม่ถือเป็น Production SLA

## 7. Deploy และตรวจสอบ
กด Deploy/Build แล้วตรวจ Build Logs และ Runtime Logs

Startup logs ที่คาดหวัง:
```text
[health] listening on 0.0.0.0:8080 (/livez, /readyz)
[gateway] connected to Discord Gateway
Logged in as SockBoi Bot — guild ... — automate ON
```

ทดสอบจาก Northflank Shell:
```bash
python -c "import urllib.request; print(urllib.request.urlopen('http://127.0.0.1:8080/livez').read().decode())"
python -c "import urllib.request; print(urllib.request.urlopen('http://127.0.0.1:8080/readyz').read().decode())"
```

จาก Discord ตรวจ Bot Online แล้วรัน `!status`, `!diag`; ทดสอบ Verify, Role Selection, Welcome, moderation, logging และ Voice Greeting (ถ้าเปิดใช้)

## 8. GitHub Auto Deploy และ CI
ไฟล์ `.github/workflows/ci.yml` ทำหน้าที่ CI:
- ติดตั้ง dependencies
- compile Python modules
- รัน unit tests
- build Docker image

การ Deploy จริงทำโดย Northflank Git integration:
1. เชื่อม Repository กับ Deployment Service
2. เลือก branch ที่ต้องการ
3. เปิด Auto Deploy / Continuous Deployment
4. Push commit ไป branch นั้น
5. Northflank build และ deploy revision ใหม่อัตโนมัติ

GitHub Actions ตรวจโค้ดและ Docker build; ไม่ใช่ตัวสั่ง Deploy ไป Northflank และไม่ต้องใช้ Northflank API token เมื่อใช้ Git integration โดยตรง

## 9. Graceful Shutdown และ Data Safety
เมื่อ Northflank ส่ง SIGTERM:
1. ปิด Discord client
2. ยกเลิก verification worker และ gateway monitor
3. บันทึก JSON ลง temporary file
4. flush + fsync แล้ว atomic replace ไปยังไฟล์จริง
5. ปิด health server และออกจาก process

ควรเห็น:
```text
[shutdown] signal received; closing Discord client
[shutdown] state saved; process stopped cleanly
```

## 10. Troubleshooting
| อาการ | วิธีตรวจ |
|---|---|
| Missing DISCORD_BOT_TOKEN | เพิ่ม Token ใน Secret Environment Variable |
| Invalid GUILD_ID | ใช้ Discord Server ID เป็นตัวเลข |
| Bot Offline | ตรวจ Token, Gateway intents และ Runtime Logs |
| Missing Access / Forbidden | ตรวจ permissions และ role hierarchy |
| Health check fail | ตรวจ bind 0.0.0.0:8080 และ probe path /livez |
| Permission denied /data | ตรวจ Volume mount และ UID/GID 10001 |
| Data หายหลัง Deploy | ตรวจ mount path /data และ DATA_DIR=/data |
| Voice ไม่ทำงาน | ตรวจ FFmpeg, libopus, Connect/Speak permissions |
| Reconnect บ่อย | ตรวจ Gateway logs, Network และ Discord status; discord.py retry อัตโนมัติ |
